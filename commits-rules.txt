Правила оформления коммитов (Conventional Commits)

Формат сообщения:
<тип>(<область>): <краткое описание>

<необязательное подробное описание>

<необязательный футер>

Область в скобках необязательна. Пример: feat(auth): add login form

Основные типы:
feat — новая функциональность
fix — исправление ошибки
docs — изменения в документации
style — форматирование кода, не влияющее на логику (пробелы, отступы)
refactor — изменение кода без новой функциональности и без исправления ошибок
perf — улучшение производительности
test — добавление или исправление тестов
build — изменения сборки и зависимостей
ci — изменения в настройках CI
chore — прочие изменения (служебные задачи)
revert — отмена предыдущего коммита

Правила:
1. Тип пишется строчными буквами, после него ставится двоеточие и пробел.
2. Описание краткое, до 50-72 символов, без точки в конце.
3. Описание пишется в повелительном наклонении: "add", "fix", "update".
4. Между заголовком и подробным описанием оставляется пустая строка.
5. Один коммит — одно логическое изменение.
6. Ломающие изменения отмечаются знаком ! после типа (feat!: ...)
   или строкой BREAKING CHANGE: в футере.

Примеры:
feat: add user registration
fix(api): handle empty response
docs: update README
refactor: simplify price calculation
feat!: remove support for old API
